Судя по тому, что у тебя уже работает (scan → entity_model → impact → snapshot → memory queries), у тебя сейчас система не “строится”, а начинает **собирать поведение в контур**. На завтра лучше не расширять функционал, а закрыть устойчивость и связность — иначе она начнёт разваливаться по краям.

Вот нормальный, реалистичный план на следующий шаг:

---

# 🧭 План на завтра (без перегруза)

## 1. 🔧 Проверка целостности memory loop (обязательно)

Цель: убедиться, что цикл реально замкнут

```
scan → impact → snapshot → memory read
```

Сделай прогон:

* scan (SicsController)
* impact (Sic)
* snapshot (sic_v1)
* memory --snapshot-show
* memory --search

📌 Проверка:

* нет ли рассинхрона entity_model vs snapshot
* одинаковые ли сущности в impact и snapshot

---

## 2. 🧠 Стабилизация state consistency

Сейчас у тебя уже есть:

* memory.db
* snapshots
* timeline
* search

Но важно проверить:

👉 одинаковая ли логика в:

* memory (sqlite)
* snapshot (json dump)
* timeline (memory.view)

📌 задача:
найти расхождения в данных (если есть)

---

## 3. 🔍 Audit entity_model pipeline (очень важно)

Прогон одного entity:

```
Sic
```

и проверить:

* scan dependencies
* graph build
* associations
* impact
* prompt

📌 цель:
убедиться, что:

> один и тот же entity проходит одинаково через все стадии

---

## 4. 📊 Проверка impact stability

Сейчас impact уже работает, но важно:

* повторить 2–3 раза один и тот же анализ
* сравнить score

📌 вопрос:

> стабильный ли impact или “плавает”

---

## 5. 🧱 Найти слабое место архитектуры (самое важное)

Сейчас потенциально слабые зоны:

* dependency_graph (очень упрощён)
* associations (могут не влиять на impact)
* enrich (может переоценивать patterns)

📌 задача:
найти 1 место, где:

> данные есть, но не влияют на результат

---

## 6. 🧠 (опционально, если будет энергия) — MEMORY sanity pass

Пройтись по:

```
memory --timeline
memory --last
memory --search Sic
```

и ответить себе:

* это реально полезная память?
* или просто лог?

---

# 🎯 Итог дня (что должно остаться)

После завтрашнего дня у тебя должно быть:

✔ стабильный memory loop
✔ одинаковое поведение snapshot / impact
✔ понимание где система “врёт” или упрощает
✔ 1–2 выявленных архитектурных слабых места

---

# 🚫 Чего НЕ делать завтра

* не добавлять новые CLI команды
* не расширять prompt system
* не усложнять memory schema
* не трогать enrichment

---

# 💡 Суть завтрашнего дня

> не строим новое — проверяем, что уже построено реально работает как система
